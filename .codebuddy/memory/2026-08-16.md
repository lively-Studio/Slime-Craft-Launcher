# 2026-08-16

## 版本号升级 DEV2026.1.0-SNAPSHOT-11 → SNAPSHOT-12
- 用户要求把版本号从 SNAPSHOT-11 升到 SNAPSHOT-12。
- 版本定义共有 5 处必须同步改（否则本地/CI 产物版本不一致，会重现更新排序 bug）：
  1. `config/project.properties` 的 `versionRoot`
  2. `.github/workflows/gradle.yml`（`SCL_VERSION`，workflow 级 env，line 17）
  3. `.github/workflows/linux-pkg.yml`（`SCL_VERSION`，line 19）
  4. `.github/workflows/macos-dmg.yml`（`SCL_VERSION`，line 20）
  5. `.github/workflows/windows-exe.yml`（`SCL_VERSION`，line 20）
- `build.gradle.kts` 优先级：`SCL_VERSION` 环境变量 > `BUILD_NUMBER` > `versionRoot`（project.properties）。CI 走 `SCL_VERSION`；本地无 env 时回退 `versionRoot`。两者必须一致。
- 另在 `CHANGELOG.md` 顶部新增 `## DEV2026.1.0-SNAPSHOT-12` 小节（发布 workflow 用 awk 按版本从 CHANGELOG 抽取 release notes，缺小节会 fallback 报错）。
- 注意：搜索工具对 `.github` 目录有时会漏索引，必要时用 `path` 参数精确指定目录再搜。
- 保留项（不要改）：`UpdateChecker.java` 注释里的 `SNAPSHOT-9`/`SNAPSHOT-11` 仅是 bug 说明示例；`SCLCore/.../versions.txt` 里的 `26.1-snapshot-11` 是 Minecraft 游戏版本，与启动器版本无关。

## 验证 VersionNumber 正确性的结论（重申）
- 用仓库真实 `VersionNumber.java` 编译运行，`compare("DEV...-SNAPSHOT-11","DEV...-SNAPSHOT-9")=+1`，证明 `VersionNumber` 比较无误；更新排序 bug 唯一真因是 `UpdateChecker.checkUpdate()` 的 `findFirst()` 创建序选取（已于 08-15 修复）。
